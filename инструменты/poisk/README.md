# poisk — поиск упоминаний в сканах дореволюционных газет

Ищет в PDF-сканах «Могилевских губернских ведомостей» упоминания заданных объектов (Ветка, Грошиковы, Рубановы — список в `config.toml`) и не переписывает весь текст.

## Как это работает

1. **scan** — каждая страница режется на плитки ~1200×1000 px в **исходном разрешении скана**, с перекрытием больше ширины колонки. Поэтому каждая строка целиком попадает хотя бы в одну плитку. Дешёвая модель (по умолчанию Claude Haiku 5.5) смотрит на плитку и возвращает короткий JSON: что найдено и цитату. Переписывать текст ей не нужно, поэтому выходных токенов почти нет.
2. Находки из перекрывающихся плиток склеиваются в **кандидатов**, и область каждого сужается до пересечения плиток.
3. **verify** — по каждому кандидату сильная модель (по умолчанию Claude Opus 5.5) смотрит увеличенную вырезку. Она подтверждает или отклоняет находку, даёт дословную цитату, контекст, рубрику, лиц и краткий смысл. Вырезка сохраняется в PNG.
4. **report** — `работа/находки.xlsx` в том же виде, что `упоминания.xlsx`: те же 16 колонок по `данные/СХЕМА.md`, цвета объектов, ссылки на фрагменты, вкладки «Все упоминания», по годам и «Просмотрено <год>». Плюс `находки.csv` (те же колонки, можно дописывать в `данные/<год>/упоминания.csv`) и `находки.md` с картинками.

   Номер выпуска, дату и страницу газеты проверяющая модель берёт из шапки страницы, тему — из текста. Колонку `раздел` (номер в реестре) заполняете вы, а `id` нумеруются заново при каждом отчёте — при переносе в свой CSV их надо продолжить.

Всё состояние хранится в `работа/poisk.db`. После прерывания (Ctrl+C, сбой сети) повторный запуск продолжает с того же места, готовое повторно не отправляется.

## Установка

```powershell
py -3.13 -m pip install -r requirements.txt
$env:ANTHROPIC_API_KEY = "sk-ant-..."
```

## Пример: 1905 год

```powershell
$G = "C:\Users\dimab\могилевские ведомости"

# 0. Оценить стоимость и посмотреть сетку плиток (без запросов к API)
py -3.13 poisk.py scan "$G\1905_01.pdf" --dry-run

# 1a. Поиск сразу (минуты)
py -3.13 poisk.py scan "$G\1905_01.pdf"
# 1b. …или через Batch API: в 2 раза дешевле, ответ от минут до 24 ч
py -3.13 poisk.py scan "$G\1905_01.pdf" "$G\1905_02.pdf" --batch
py -3.13 poisk.py collect --wait

# 2. Проверка кандидатов и вырезки
py -3.13 poisk.py verify

# 3. Отчёт
py -3.13 poisk.py report          # без отклонённых
py -3.13 poisk.py report --all    # с отклонёнными (добавится колонка «статус») — для контроля глазами

py -3.13 poisk.py status          # прогресс и расходы
```

`--pages 1-20,25` ограничивает страницы. Большие сборные PDF (300+ МБ) открываются без копирования.

## Проверка надёжности на ваших эталонных данных

В `данные/1892/упоминания.csv` уже есть 7 проверенных вручную находок на стр. PDF 1–70 файла `1892_001-026.pdf`. Прежде чем доверять поиску на новых годах, прогоните:

```powershell
py -3.13 poisk.py scan   "$G\1892_001-026.pdf" --pages 1-70
py -3.13 poisk.py verify
py -3.13 poisk.py eval   "$G\1892_001-026.pdf" --pages 1-70 --truth "$G\данные\1892\упоминания.csv"
```

`eval` покажет, какие эталонные находки найдены, а какие пропущены, сколько лишних кандидатов и сколько это стоило. Если Haiku что-то пропускает, повторите с более сильной моделью и сравните. Результаты разных моделей хранятся отдельно:

```powershell
py -3.13 poisk.py scan "$G\1892_001-026.pdf" --pages 1-70 --model claude-sonnet-5-5 --batch
py -3.13 poisk.py collect --wait
py -3.13 poisk.py verify --scan-model claude-sonnet-5-5
py -3.13 poisk.py eval "$G\1892_001-026.pdf" --pages 1-70 --truth "$G\данные\1892\упоминания.csv" --model claude-sonnet-5-5
```

Подходящую модель запишите в `config.toml` → `[models] scan`.

## Полная расшифровка (по желанию)

```powershell
py -3.13 poisk.py transcribe "$G\1892_001-026.pdf" --pages 57-59
```

Страница режется на горизонтальные полосы во всю ширину с перекрытием. Красная линия на картинке показывает модели, что уже расшифровано, поэтому строки на стыках не теряются и не дублируются. Текст пишется в `работа/тексты/<файл>.txt` по полосам, а внутри полосы — по колонкам слева направо. Это дорого (весь текст — выходные токены), поэтому имеет смысл только для страниц с находками.

Полосы шире 2576 px (сканы 1892 года — 3000 px) API немного уменьшает; для крупного шрифта 1892 года этого достаточно.

## Расходы (оценка `--dry-run`)

| Объём | Haiku 5.5 | Haiku 5.5, Batch | Sonnet 5.5, Batch |
|---|---|---|---|
| 1905_01.pdf, 17 стр. | ≈ $0.12 | ≈ $0.06 | ≈ $1.2 |
| 1892, 70 стр. | ≈ $0.73 | ≈ $0.36 | ≈ $7.3 |

Проверка (verify) стоит несколько центов за кандидата и запускается только для найденного. Фактические расходы показывает `status`.

## Настройки — `config.toml`

- `[[target]]` — что искать: описание и примеры написания в дореформенной орфографии. Добавьте блок, чтобы искать новую фамилию или село.
- `[models]` — модели и уровень усилия (`effort`) для поиска, проверки и расшифровки.
- `[tiles]` — размер плиток и перекрытие. `overlap_x` должен быть больше ширины самой широкой колонки.
- `[run] workers` — число одновременных запросов. Уменьшите, если API часто отвечает 429.

## Чем отличается от прежнего Java-приложения (`pl.analyzer\src`)

- Скан не перерендеривается в 300 DPI (это раздувало картинку 2448×3264 до ~10200×13600 и потом снова сжимало).
- Колонки не нужно угадывать: перекрывающиеся плитки не режут строки.
- Модель не переписывает страницу целиком, поэтому выходных токенов в десятки раз меньше и меньше места для досочинённого текста.
- Каждая находка проверяется второй моделью по вырезке и сохраняется картинкой — её можно проверить глазами.
- Нет лимита размера загрузки: файлы читаются с диска.
